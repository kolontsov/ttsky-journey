# song.json Format

This file describes the narrow composition format used by
`scripts/data/song.json`.

The JSON is not a general tracker format. It is a compact source format for the
fixed Journey hardware song engine.

## Fixed Model

- Song length is fixed at 32 bars.
- The top-level `arrangement` has exactly 8 slots.
- Each arrangement slot names one 4-bar section.
- Each section has fixed tracks: `kick`, `snare`, `hat`, `bass`, `melody`.
- One bar has 16 positions, numbered `0..15`.
- Position units are sixteenth notes.
- Tempo, instrument sounds, envelopes, volumes, and effects are fixed by code.
- Do not add channels, durations, volumes, effects, instruments, or note-off
  events to JSON. They have no representation in the hardware format.

The playback/generation reference is `scripts/engine_song.py`. Hardware pattern
SV is generated by `scripts/gen_patterns.py`.

## Top-Level Fields

```json
{
  "description": "...",
  "key": "A minor",
  "gamut": ["A", "B", "C", "D", "E", "F", "F#", "G#"],
  "arrangement": ["A", "B", "A", "C", "A", "B", "A", "C"],
  "sections": { "...": { "tracks": { "...": [] } } }
}
```

`description` is human-readable context.

`key` is human-readable context and Furnace metadata. It does not transpose or
retune anything by itself.

`gamut` is the global note set for the whole song. It must contain exactly 8
unique pitch classes. Notes in `bass` and `melody` must use pitch classes from
this list. The current hardware note table is built for:

```json
["A", "B", "C", "D", "E", "F", "F#", "G#"]
```

Do not change `gamut` unless the note table and tooling are being changed on
purpose. The order matters: each entry maps to a fixed hardware note index.

`arrangement` must contain exactly 8 section names. Sections not referenced by
`arrangement` may exist as scratch/editor material, but they are not compiled
into the hardware song by `engine_song.load_song()`.

`sections` maps section names to 4-bar musical sections.

## Section Structure

Each section has this shape:

```json
"A": {
  "tracks": {
    "kick":   [[0, 4, 8, 12]],
    "snare":  [[4, 12]],
    "hat":    [[2, 4, 6, 10, 12, 14]],
    "bass": [
      [[0, "A1"], [2, "A1"], [4, "E2"], [6, "A1"], [8, "A1"], [10, "A1"], [12, "E2"], [14, "A2"]],
      [[0, "F#2"], [2, "F#2"], [4, "C2"], [6, "F#2"], [8, "F#2"], [10, "F#2"], [12, "C2"], [14, "F#3"]],
      [[0, "B1"], [2, "B1"], [4, "F2"], [6, "B1"], [8, "B1"], [10, "B1"], [12, "F2"], [14, "B2"]],
      [[0, "E2"], [2, "E2"], [4, "A1"], [6, "E2"], [8, "E2"], [10, "E2"], [12, "A1"], [14, "E3"]]
    ],
    "melody": [
      [[0, ["A3", "C4"]], [2, ["C4", "E4"]], [8, ["E4", "A4"]], [10, ["C4", "E4"]]],
      [[0, ["F#4", "C4"]], [2, ["C4", "E4"]], [8, ["E5", "F#5"]], [10, ["C4", "E4"]]],
      [[0, ["B3", "D4"]], [2, ["D5", "F#5"]], [8, ["F#5", "A4"]], [10, ["D5", "F#5"]]],
      [[0, ["E4", "G#4"]], [2, ["G#4", "C5"]], [8, ["C5", "E5"]], [10, ["G#4", "C5"]]]
    ]
  }
}
```

Track bar lists may contain 1, 2, or 4 bars. A 1-bar track repeats four times;
a 2-bar track repeats twice. An empty drum track is silence. Bass and melody
should normally provide 4 bars unless an intentional repeating pattern is
wanted.

## Drum Tracks

`kick`, `snare`, and `hat` are arrays of bars. Each bar is an array of integer
positions:

```json
"kick": [[0, 4, 8, 12]]
```

Rules:

- Positions must be integers in `0..15`.
- Duplicates are pointless and should be avoided.
- Missing drum tracks are treated as silent.
- `snare` and `hat` share the same hardware noise channel.
- If snare and hat fire on the same position, snare wins and the hat is
  inaudible.
- Furnace import canonicalizes this by not restoring hidden hat hits under
  snare hits.

## Bass Track

`bass` is an array of bars. Each bar must contain exactly one event on every
eighth note:

```json
[[0, "A1"], [2, "E2"], [4, "A1"], [6, "A2"], [8, "E2"], [10, "A1"], [12, "D2"], [14, "E2"]]
```

Rules:

- Positions must be exactly the even positions `0, 2, 4, 6, 8, 10, 12, 14`.
- Every even position must have a note. Bass rests are not supported.
- Notes must use pitch classes from the global `gamut`.
- Notes must be in the bass hardware range.

For the current gamut, valid bass notes are:

```text
A1 B1 C2 D2 E2 F2 F#2 G#2
A2 B2 C3 D3 E3 F3 F#3 G#3
```

The general octave rule is:

- For `A` and `B`, bass octaves are `1` and `2`.
- For `C` through `G#`, bass octaves are `2` and `3`.

Kick masks the bass while the kick envelope is active. This is intentional
sidechain-style ducking in the hardware mixer.

## Melody Track

`melody` is an array of bars. Each event is:

```json
[position, [main_note, arp_note]]
```

Example:

```json
[8, ["E4", "A4"]]
```

If both notes are the same, the shorthand form is allowed:

```json
[8, "E4"]
```

Rules:

- Positions are sixteenth positions in `0..15`.
- For current hardware generation, use even positions only:
  `0, 2, 4, 6, 8, 10, 12, 14`.
- Melody rests are allowed by omitting events.
- Notes must use pitch classes from the global `gamut`.
- Notes must be in the melody hardware range.
- `main_note` and `arp_note` start together. They are not two independent
  channels with separate timing.

For the current gamut, valid melody notes are:

```text
A3 B3 C4 D4 E4 F4 F#4 G#4
A4 B4 C5 D5 E5 F5 F#5 G#5
```

The general octave rule is:

- For `A` and `B`, melody octaves are `3` and `4`.
- For `C` through `G#`, melody octaves are `4` and `5`.

The hardware alternates the main and arp pitches at a fixed sub-row rate and
applies a fixed decay/tremolo behavior. JSON does not control melody duration,
volume, duty cycle, or effect timing.

## Validation

Preview a candidate song:

```sh
uv run scripts/play_song.py --song scripts/data/song.imported.json
```

Generate SystemVerilog from a candidate without overwriting the checked-in
hardware pattern file:

```sh
uv run scripts/gen_patterns.py --song scripts/data/song.imported.json --dry-run
```

Write generated patterns from a candidate:

```sh
uv run scripts/gen_patterns.py --song scripts/data/song.imported.json --out src/synth_patterns.sv
```

`make gen` uses `scripts/data/song.json`. To test another JSON file, call
`scripts/gen_patterns.py --song ...` directly.
